= Protégez les charges de travail Microsoft SQL Server avec Workload Factory for Databases
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
Protégez les données de votre application Microsoft SQL Server avec NetApp Backup and Recovery depuis la console Workload Factory. Grâce à cette intégration, vous pouvez sauvegarder les charges de travail avec des instantanés locaux sur le stockage principal Amazon FSx for NetApp ONTAP (FSx for ONTAP) et répliquer les charges de travail vers un stockage secondaire FSx for ONTAP.



[[about-this-task]]
== Description de la tâche

Workload Factory automatise la découverte des ressources, la validation des prérequis, ainsi que la configuration et l'installation du plug-in pour Microsoft SQL Server afin de préparer la protection de vos charges de travail avec NetApp Backup and Recovery. Le plug-in est un composant côté hôte du logiciel NetApp qui vous permet de protéger vos charges de travail Microsoft SQL Server.

NetApp Backup and Recovery utilise la technologie de réplication des données NetApp SnapMirror pour garantir que toutes les sauvegardes sont entièrement synchronisées en créant des copies Snapshot et en les transférant vers les emplacements de sauvegarde.

Pour plus de détails sur la protection avec Backup and Recovery, reportez-vous au link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-mssql-protect-overview.html["Présentation de la protection des charges de travail Microsoft SQL avec la sauvegarde et la récupération"^].



[[before-you-begin]]
== Avant de commencer

Répondez à ces exigences avant de protéger les charges de travail Microsoft SQL Server avec Backup and Recovery.

* Assurez-vous que votre environnement répond link:https://docs.netapp.com/us-en/data-services-backup-recovery/concept-start-prereq.html#microsoft-sql-server-workload-requirements["les exigences de sauvegarde et de récupération de SQL Server"^].
* link:https://docs.netapp.com/us-en/data-services-backup-recovery/concept-start-prereq.html#in-netapp-console["Configuration requise complète de la console NetApp"^], y compris la configuration, l’attribution des rôles IAM et l’installation d’un agent Console.


Si vous disposez d'un accès administrateur d'organisation au compte NetApp , le `backup and recovery super admin` le rôle est automatiquement attribué lorsque vous<<Préparez-vous à la protection avec NetApp Backup and Recovery,préparez-vous à la protection avec NetApp Backup and Recovery>> .

* Configurez la résolution de l’hôte sur l’agent Console
+
Pour découvrir les bases de données, vous devez configurer la résolution d’hôte sur l’agent Console. Sur le périphérique hébergé, ajoutez la correspondance entre l’adresse IP et le nom d’hôte dans le fichier `/etc/hosts`.

+
** link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-start-licensing.html["Configurer les licences pour NetApp Backup and Recovery"^]






[[prepare-for-protection-with-netapp-backup-and-recovery]]
== Préparez-vous à la protection avec NetApp Backup and Recovery

Terminez le processus de préparation pour protéger vos ressources Microsoft SQL Server avec NetApp Backup and Recovery.

.Étapes
. Connectez-vous à l'aide de l'un des link:https://docs.netapp.com/us-en/workload-setup-admin/console-experiences.html["expériences de la console"^].
. Sélectionnez le menu image:workloads-menu-icon.png["L'icône du menu hamburger permet d'accéder aux charges de travail telles que le stockage, l'analyse de données d'entreprise (EDA), l'intelligence artificielle (IA), les bases de données, VMware et l'administration."] puis sélectionnez *Bases de données*.
. Dans le menu Bases de données, sélectionnez *Inventaire*.
. Dans l’inventaire, sélectionnez *Microsoft SQL Server* comme type de moteur.
. Localisez l’instance que vous souhaitez protéger, puis sélectionnez *Protéger* dans le menu.
. Si vous y êtes invité, fournissez les informations d’identification Windows avec accès administratif.
+
Pour utiliser NetApp Backup and Recovery pour la protection, les instances SQL Server doivent être enregistrées dans Workload Factory avec les informations d'identification Windows.

. Si plusieurs agents de console sont actifs et disponibles, sélectionnez l'*agent de console* dans lequel vous souhaitez que la charge de travail soit enregistrée et protégée.
. Sélectionnez *Démarrer* pour préparer la protection des données. Workload Factory enregistre automatiquement vos ressources SQL Server dans Backup and Recovery, configure et installe le Plug-in for Microsoft SQL Server, et détecte les ressources nécessaires pour remplir les prérequis de protection de votre instance SQL Server.
. Une fois les conditions préalables remplies, sélectionnez *Redirect* pour accéder à Backup and Recovery.


.Et la suite
À partir de Sauvegarde et récupération, créez une stratégie pour protéger votre instance et vos bases de données Microsoft SQL Server.

link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-policies-create.html["Découvrez comment créer une politique pour protéger votre instance et vos bases de données Microsoft SQL Server"^].

Pour des informations connexes, reportez-vous à la link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-mssql-protect-overview.html["Documentation de sauvegarde et de récupération"^] pour gérer les charges de travail Microsoft SQL Server.



[[edit-protection-for-microsoft-sql-server-resources]]
== Protection contre la modification des ressources Microsoft SQL Server

Vous pouvez modifier la protection des instances et des bases de données Microsoft SQL Server déjà protégées dans NetApp Backup and Recovery. La modification de la protection vous permet de modifier la stratégie ou la planification de protection de vos instances SQL Server protégées.

. Connectez-vous à l'aide de l'un des link:https://docs.netapp.com/us-en/workload-setup-admin/console-experiences.html["expériences de la console"^].
. Sélectionnez le menu image:workloads-menu-icon.png["L'icône du menu hamburger permet d'accéder aux charges de travail telles que le stockage, l'analyse de données d'entreprise (EDA), l'intelligence artificielle (IA), les bases de données, VMware et l'administration."] puis sélectionnez *Bases de données*.
. Dans le menu Bases de données, sélectionnez *Inventaire*.
. Dans l’inventaire, sélectionnez *Microsoft SQL Server* comme type de moteur.
. Sélectionnez l'onglet *Bases de données*.
. Localisez la base de données dont vous souhaitez modifier la protection, puis sélectionnez *Modifier la protection* dans le menu.
+
Vous serez redirigé vers la section Sauvegarde et restauration de la NetApp Console où vous pourrez modifier la politique ou la planification de protection.
